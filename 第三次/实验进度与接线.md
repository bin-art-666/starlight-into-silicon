# 实验三：TFTP 与 NFS（准备阶段历史记录）

> 两项板上实验均已完成。最终配置、真实结果与后续操作见同目录《实验完成记录.md》，以下保留早期准备记录。

## 任务范围

1. U-Boot 通过 TFTP 下载裸机 C 程序，并从内存执行。
2. 开发板启动 Linux，挂载 NFS 程序目录，运行普通 ARM Linux C 程序。

本次不要求使用 NFS 作为完整根文件系统，不需要为此修改永久启动参数。

## 接线

- 网线插开发板 ENET2（老师提供资料的明确要求）。
- 可选：开发板接路由器 LAN，电脑接同一路由器的 Wi-Fi 或网线；双方必须能够互通。
- 或者：开发板直连电脑的实体网口。当前电脑检测到的“以太网 2”为 VPN 虚拟网卡，不能当成实体接口；若无实体接口，需要 USB 转以太网适配器。
- 串口 USB 线负责操作 U-Boot/Linux 和查看日志，不能代替网线。
- 上次 SD 卡保留裸机 LED 熄灭镜像；本次需启动带 U-Boot/Linux 的系统，先确认启动介质及拨码。

## 已实测（2026-10-16）

- WSL sweet，Ubuntu 24.04，安装 tftpd-hpa、tftp-hpa、nfs-kernel-server、nfs-common、rpcbind。
- TFTP 根目录 `/srv/tftp`：包含 `tftp_test.txt`、既有裸机程序 `ledc.bin`。
- 本机 TFTP 实际下载两份文件，内容校验一致。
- NFS 目录 `/srv/nfs/lab3`：包含 `hello_nfs.c`、`hello_nfs_arm`。
- 普通 C 程序已编译为 ARM 32 位静态 Linux ELF，含调试信息，最低内核标记为 3.2.0。
- NFSv3/TCP 本机挂载成功，挂载路径读取 ELF 的 SHA256 与服务端一致。
- 两个服务运行正常。完整输出见 `实测记录/服务端验证.log`。

## 待网络打通后使用的命令模板

下列 SERVER_IP、BOARD_IP、MASK 必须替换为实际地址；不需要执行 saveenv。

U-Boot：

```text
setenv ipaddr BOARD_IP
setenv serverip SERVER_IP
setenv netmask MASK
ping SERVER_IP
tftp 0x87800000 ledc.bin
```

确认传输成功、大小为 588 字节，并核对实际 U-Boot 内存布局及缓存状态后，再执行 `go 0x87800000` 观察 LED。这里下载的是无 SD 启动头的 `ledc.bin`，不是 `load.imx`。LED 程序不会返回 U-Boot，结束后需复位。

开发板 Linux（网卡名称先通过 ifconfig -a 或 ip link 确认）：

```sh
mkdir -p /mnt/lab3
mount -t nfs -o vers=3,proto=tcp,nolock SERVER_IP:/srv/nfs/lab3 /mnt/lab3
/mnt/lab3/hello_nfs_arm
umount /mnt/lab3
```

预期打印程序标题以及 1 到 5 的平方。以上为预期结果，尚无板上实测记录。
