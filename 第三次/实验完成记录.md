## TFTP 裸机运行

复用已验证的 c_500 LED 裸机 C 程序，文件为本目录 tftp/ledc.bin。

U-Boot 命令：

```text
setenv ipaddr 192.168.1.4
setenv serverip 192.168.1.100
setenv netmask 255.255.255.0
tftp 0x87800000 ledc.bin
crc32 0x87800000 0x24c
dcache off
icache off
go 0x87800000
```

实测传输 588 字节（0x24c），内存 CRC32 为 2658fc5a，与本机文件一致。串口打印 Starting application at 0x87800000，用户确认“用户 LED 正在闪烁”。已核对下载地址位于 512 MiB DDR 内，未覆盖 U-Boot 重定位区域。

未执行 saveenv，未烧写 SD/eMMC。下载的是无 SD 启动头的 ledc.bin。

证据：实测记录/UBoot_TFTP下载.txt、实测记录/UBoot_裸机C程序跳转.txt。

## NFS 普通 Linux C 程序运行

源码 hello_nfs.c，WSL 编译命令：

```sh
arm-linux-gnueabihf-gcc -static -O0 -g -Wall -Wextra hello_nfs.c -o nfs/hello_nfs_arm
```

程序为 ARM 32 位静态 Linux ELF，含调试信息，需要 Linux 环境。

开发板命令：

```sh
mkdir -p /mnt/lab3
mount -t nfs -o vers=3,proto=tcp,nolock,soft,timeo=20,retrans=1 192.168.1.100:/lab3 /mnt/lab3
/mnt/lab3/hello_nfs_arm
echo $?
```

实测输出：

```text
Lab 3: Linux C program running from NFS.
1 * 1 = 1
2 * 2 = 4
3 * 3 = 9
4 * 4 = 16
5 * 5 = 25
NFS_RUN_EXIT=0
```

/proc/mounts 确认程序来自 192.168.1.100:/lab3 的 NFSv3/TCP 挂载，WinNFSd 的 mountport 为 1058。

Linux 中另外成功通过 TFTP 下载 ledc.bin，退出码 0、588 字节，SHA256 与本机一致：486f6e908074d25b2c80813b93de430dd0d9ad288fb50e49eb97b3c501d8f0a9。

证据：实测记录/开发板下载与NFS运行验证.txt（含命令、挂载信息和退出码）。
