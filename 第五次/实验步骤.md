# 实验操作与复现步骤

工作目录：`D:\Develop\Linux\嵌入式\第五次`。开发板目录：`/home/root/lab5`。串口：COM3、115200、8N1。

## 1. 检查现有驱动

在开发板执行：

```sh
uname -a
cat /proc/asound/cards
cat /proc/asound/pcm
ls -l /dev/snd
aplay -l
arecord -l
zcat /proc/config.gz | grep -E 'CONFIG_(SOUND|SND|SND_SOC|SND_SOC_IMX_WM8960|SND_SOC_FSL_SAI|SND_SOC_FSL_ASRC)='
```

实测声卡 0 为 `wm8960-audio`，设备 0 为 `HiFi wm8960-hifi-0`，设备 1 为 ASRC 前端。六项内核配置均为 `y`，`aplay`、`arecord`、`amixer`、`alsamixer` 均已安装，aplay 版本为 1.1.0。

教程的内核配置、设备树和 ALSA 移植用于缺少驱动或工具的系统。本板已满足这些条件，直接验证实际功能；不要为重复教程而覆盖现有内核或系统库。

## 2. 备份和设置播放

```sh
cd /home/root/lab5
# 首次操作前执行；复现实验时不要覆盖最初备份。
test -f mixer-before.state || alsactl -f mixer-before.state store
sh playback_config.sh
aplay -D hw:0,0 lab5_music.wav
echo $?
```

播放文件为 44.1 kHz、16 位、小端、有符号、双声道 PCM，因此可直接使用 `hw:0,0`，不需要格式转换。脚本启用两路 PCM 输出并设置耳机和扬声器音量，未照搬教程接近最大值的音量。

## 3. 配置板载麦克风并录音回放

```sh
sh mic_config.sh left1
arecord -D hw:0,0 -f cd -d 10 record.wav
echo $?
aplay -D hw:0,0 record.wav
echo $?
```

实测采用板端初始已选择的 LINPUT1 通路。脚本开启左输入 Boost 通路，关闭其他模拟输入，将 Capture 设为 35/63、ADC PCM 设为 195/255。

当前驱动提供 `ADC Data Output Select`，枚举 1 将左 ADC 复制至左右数字声道。因此无需按教程修改驱动默认寄存器并重编内核。左右声道相同是预期结果。

教程中 `Playback 256`、部分 Boost 控件 `127` 超过本板控件范围，且本板不存在同名 `PCM Playback` 开关，不能逐字复制。具体范围已保存在 `实测记录/02_驱动与混音器基线.txt`。

## 4. 保存与恢复

```sh
alsactl -f mixer-lab5.state store
alsactl -f mixer-lab5.state restore
```

本次先将耳机音量临时改为 80，再恢复实验配置，实际恢复到 105，退出码为 0。

系统已有 `/etc/init.d/alsa-state` 和 `/etc/rcS.d/S39alsa-state`，从 `/var/lib/alsa/asound.state` 恢复配置。原文件已备份到 `/home/root/lab5/system-asound-before.state`，本次已调用 `alsactl` 将实验设置写入系统状态文件。没有追加重复的启动脚本，也没有重启。

恢复实验前的即时混音器状态：

```sh
cd /home/root/lab5
alsactl -f mixer-before.state restore
```

如需同时恢复原系统保存文件：

```sh
cd /home/root/lab5
cp -p system-asound-before.state /var/lib/alsa/asound.state
alsactl -f /var/lib/alsa/asound.state restore
```

## 5. 证据与限制

`09_播放录音回放实测.txt` 保存三个步骤的成功退出码；用户随后确认旋律与回放均可听到。原始录音经串口传输并验证 SHA-256，主机未对其音量、声道或内容进行加工。

板端 RTC 显示 2021-07-22，与实际日期 2026-10-16 不一致，日志保留原始时间。当前只验证板载喇叭和板载麦克风；耳机自动切换、LINE IN、重新编译驱动、重启恢复不计为已验证项目。
