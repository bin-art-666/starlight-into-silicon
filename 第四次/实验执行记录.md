## 本次处理的问题

1. 出厂设备树使用 `/leds/beep`，原 gpio-leds 已占用蜂鸣器。实验 DTB 禁用这个子节点，从 leds 的 pinctrl 中移除蜂鸣器引用，保留系统 LED，然后增加根节点 `/beep`。
2. 实际蜂鸣器 pinctrl 位于 SNVS 控制器。工作版驱动显式选择该设备的 default pinctrl，随后申请 GPIO。
3. 当前 Linux 内核不同于课程故障资料中的纯 4.1.15。使用匹配出厂源码和真实配置构建，没有强制加载或绕过版本校验。模块加载成功说明其导入符号通过了本次运行内核的版本检查。
4. 主机默认 GCC 13 编译旧内核失败；改用本机既有的 Linaro GCC 5.5 成功。失败日志保留用于说明问题，复现实验以 GCC 5.5 成功日志和构建脚本为准。
5. 原 NFS 服务无响应。保留地址和共享目录重启 WinNFSd 后，原挂载出现 Stale file handle，重新挂载到 `/mnt/lab4` 后恢复读写。

## 当前可重复的开关操作

```sh
cd /tmp/lab4
./beepApp /dev/beep 1
sleep 1
./beepApp /dev/beep 0
```

结束时保持关闭。若要卸载，执行 `rmmod beep`；若要重新加载，执行 `insmod /tmp/lab4/beep.ko`。
