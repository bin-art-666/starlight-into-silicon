# 实验四：Linux 蜂鸣器驱动实验步骤

## 1. 本次实际环境

- 开发板：正点原子 i.MX6ULL，运行出厂 Linux。
- 实测内核：`4.1.15-g3dc0a4b`，出厂内核编译器 GCC 5.3.0。
- 串口：COM3，115200，8N1。
- 开发板地址：`192.168.1.4/24`；电脑地址：`192.168.1.100/24`，使用开发板 ENET2。
- 主机编译环境：WSL sweet，ARM Linux 交叉编译器。
- 资料：开发手册第 46 章，1195–1205 页。

实际环境与老师故障整理 PDF 中的 Ubuntu 16.04、4.1.15 环境不同，需要使用实测参数。

## 2. 确认网络、内核与现有设备

在开发板 Linux 串口执行：

```sh
uname -a
cat /proc/version
ifconfig eth0
ping -c 2 192.168.1.100
ls /proc/device-tree/beep /dev/beep
ls /sys/class/leds
cat /sys/kernel/debug/gpio
```

本次初检：网络通过；没有 `/beep` 和 `/dev/beep`，出厂蜂鸣器位于 `/sys/class/leds/beep`，GPIO5_IO01 已由 gpio-leds 使用。

硬件预检（已操作，声音由现场确认）：

```sh
echo 1 > /sys/class/leds/beep/brightness
sleep 1
echo 0 > /sys/class/leds/beep/brightness
```

此步骤验证原有接口，不替代本次字符设备驱动实验。

## 3. 备份并准备匹配的内核

保存 `/proc/config.gz`、`/sys/firmware/fdt`，本次已通过串口备份至 `实测记录/board-config.gz`、`实测记录/board.dtb`。

使用资料中的 `linux-imx-4.1.15-2.1.0-g3dc0a4b-v2.7.tar.bz2`，按开发板真实配置准备内核。启用了 CONFIG_MODVERSIONS，需要匹配构建的 Module.symvers；不能仅修改版本字符串或强制加载。

本次临时内核构建目录为 `/tmp/lab4-kernel`，源码压缩包保存在本实验目录。主机 GCC 13 与旧内核存在兼容问题。本次已使用现成 Linaro GCC 5.5 成功构建 vmlinux 和 Module.symvers；设备树工具使用 HOSTCFLAGS="-O2 -fcommon" 兼容新主机 GCC。

## 4. 修改设备树，释放原有蜂鸣器占用

1. 以实际运行设备树为基准，保存原文件。
2. 从 `/leds` 的 `pinctrl-0` 中移除蜂鸣器 pinctrl 引用，保留系统 LED。
3. 禁用 `/leds/beep` 子节点，释放 GPIO5_IO01。
4. 在根节点添加 `/beep`，指定 `compatible = "atkalpha-beep"`、`pinctrl-names = "default"`、蜂鸣器 pinctrl 及 `beep-gpio`。
5. 本板蜂鸣器 pinctrl 位于 SNVS 控制器，使用现有 SNVS_TAMPER1 → GPIO5_IO01 配置。不要将手册中旧版本设备树的节点位置机械套用到出厂设备树。
6. 编译新的 DTB，优先通过 U-Boot 网络加载进行临时验证，保留原内核和原 DTB；启动前核对地址及启动命令。
7. 重启后确认 `/proc/device-tree/beep` 存在，且 GPIO129 未被出厂 gpio-leds 占用。

## 5. 编译驱动及测试程序

工作源码在 `06_beep`，配套原始例程在 `06_beep_原始例程`。

驱动按第 46 章路线使用设备树、GPIO 和字符设备，提供 `/dev/beep`。工作版本补充了写入长度检查、copy_from_user 返回值检查、初始化失败清理，以及卸载关闭蜂鸣器；原始例程保留用于对照。工作版本还通过设备树对应的平台设备显式选择 default pinctrl，适配本板出厂设备树的 SNVS 控制器。

```sh
cd <本实验目录>/06_beep
make KERNELDIR=/tmp/lab4-kernel CROSS_COMPILE=/home/little/lab7-sdk/gcc-linaro-5.5.0-2017.10-x86_64_arm-linux-gnueabihf/bin/arm-linux-gnueabihf- module
make app
file beep.ko beepApp
```

实际编译器和内核编译参数需要与最终成功的构建记录一致。测试程序静态链接，避免开发板旧 glibc 与新主机运行库不兼容。

## 6. 通过网络传输并加载

本机已有 NFS 共享 `/lab3`，用于实验文件传输。本次初检旧挂载无响应，重启服务并重新挂载后已实测读写通过，传输成功。旧 /mnt/lab3 可能仍有失效文件句柄，使用新挂载 /mnt/lab4。

```sh
mkdir -p /mnt/lab4
mount -t nfs -o vers=3,proto=tcp,nolock,soft,timeo=20,retrans=1 192.168.1.100:/lab3 /mnt/lab4
```

将编译结果放入实际共享目录中的 lab4 子目录后，在开发板操作：

```sh
mkdir -p /tmp/lab4
cp /mnt/lab4/lab4/beep.ko /tmp/lab4/
cp /mnt/lab4/lab4/beepApp /tmp/lab4/
cd /tmp/lab4
chmod +x beepApp
insmod beep.ko
dmesg | tail -n 20
ls -l /dev/beep
```

若有符号版本错误，应回查源码、配置和符号表的构建一致性，保留实际报错。

## 7. 测试并记录

```sh
./beepApp /dev/beep 1
sleep 1
./beepApp /dev/beep 0
cat /sys/kernel/debug/gpio
rmmod beep
dmesg | tail -n 20
```

预期：开启时鸣叫，关闭后停止；卸载后蜂鸣器关闭、设备节点消失。命令成功和 GPIO 变化只能证明软件路径，声音需要现场观察确认。

## 本次临时启动命令（已执行）

已确认 DDR 为 0x80000000–0x9fffffff，原内核加载到 0x80800000，DTB 加载到 0x83000000，不与 U-Boot 重定位区重叠。

```text
mmc dev 1
run loadimage
setenv serverip 192.168.1.100
setenv ipaddr 192.168.1.4
tftp 0x83000000 lab4-beep.dtb
fdt addr 0x83000000
fdt print /beep
crc32 0x83000000 0x9b40
run mmcargs
bootz 0x80800000 - 0x83000000
```

本次 DTB 大小 39744 字节，CRC32 为 a5deaa79，板端与本机一致。未执行 saveenv，未替换 eMMC 中原有 DTB 和 zImage。重启后默认恢复原出厂设备树；要重复本次驱动实验，需要再次加载实验 DTB。

在 WSL 中可运行本目录 `bash 构建实验.sh` 复现源码构建，默认使用本次已找到的 GCC 5.5 工具链路径。
