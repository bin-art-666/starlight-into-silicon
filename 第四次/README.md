# 实验四 · 芯弦有声

## 目标与硬件

通过设备树、Linux 字符设备驱动及用户程序控制蜂鸣器，完成加载、开关、卸载和重新加载。蜂鸣器使用 SNVS_TAMPER1 / GPIO5_IO01（旧式全局编号 129），低电平响、高电平关。

## 实现与关键问题

- `06_beep/beep.c`：实际验证的驱动；`beepApp.c`：写二进制开关命令的用户程序；`gpio_readback.c`：只读检查 GPIO 寄存器。
- `设备树/lab4-beep.dts`：禁用原 `/leds/beep`，从原 leds 的 pinctrl 移除蜂鸣器引用并新增 `/beep`，避免原 gpio-leds 占用。
- 在 SNVS 引脚控制器中显式选择 default pinctrl 后申请 GPIO。
- 使用与板端 `4.1.15-g3dc0a4b` 对应的厂商源码、板端配置和 Linaro GCC 5.5 构建内核及模块。没有强制加载或绕过符号版本检查。

旧内核用主机默认 GCC 13 构建失败，改用 GCC 5.5 成功。版本字符串相同不能证明模块兼容，还要匹配构建配置与 `Module.symvers`。

## 构建和运行

先按 `资料索引.md` 获取对应源码包，准备工具链并审阅 `构建实验.sh`。临时设备树通过 U-Boot 载入内存，配合原 eMMC 的 zImage 启动；不持久修改启动环境。复位会恢复出厂设备树，单独执行 insmod 不能替代前面的设备树启动步骤。

已按 `实验步骤.md` 完成临时启动和部署后，在板端运行：

```sh
cd /tmp/lab4
insmod ./beep.ko
./beepApp /dev/beep 1
./beepApp /dev/beep 0
rmmod beep
```

## 实测结果与边界

模块加载、开关与卸载退出码均为 0，再次加载通过；现场确认开启鸣叫、关闭停止。GPIO5 DR bit1 在开/关时分别为 0/1，GDIR bit1=1。PSR 两次均为 0，不能将其解释为已测量到引脚电压变化。

设备树传输 39744 字节，CRC32 `a5deaa79`。最终记录为 `实验执行记录.md`；配置、原始 DTB、构建日志、符号表和串口日志见 `实测记录/`。`实验资料说明.md` 属于准备阶段，涉及“尚未实测”的历史表述以完成记录为准。
