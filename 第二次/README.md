# 实验二 · 灯火初明

## 目标与原理

在 I.MX6ULL ALPHA 上直接配置寄存器控制用户 LED，理解启动汇编、时钟、引脚复用、GPIO 方向与输出。用户 LED 对应 GPIO1_IO03，低电平亮，高电平灭。

## 工程与过程

| 工程 | 逻辑 | 现场结果 |
| --- | --- | --- |
| `工作工程/asm_on` | 汇编输出低电平 | 用户 LED 常亮 |
| `工作工程/asm_off` | 汇编输出高电平 | 电源灯亮、用户 LED 熄灭 |
| `工作工程/c_500` | C 循环亮灭、`delay(500)` | LED 闪烁 |
| `工作工程/c_3000` | C 循环亮灭、`delay(3000)` | 亮灭持续时间明显变长 |

`start.S` 设置 SVC 模式和栈后进入 `main`，链接地址为 `0x87800000`。编译参数显式使用 `-mcpu=cortex-a7 -marm -fno-pie -ffreestanding`，适配当前 Ubuntu 交叉编译器。四组工程均保留源码、构建日志、BIN/ELF、反汇编和小型启动镜像。

```sh
cd 工作工程/c_500
make clean
make
```

SD 启动需要带 IVT/DDR 初始化数据的 `load.imx`；裸 `ledc.bin` 用于后续 U-Boot 内存下载。两者不能混用。历史烧录向整卡偏移 1024 字节写入启动镜像，并验证读回内容及范围外数据。

## 结果与证据

四组程序均完成编译、烧录读回校验及现场效果确认，证据见 `实测记录/flash_log.jsonl`、`image_validation.json`、`LED实验现象记录.md` 和 `build_results.json`。忙等待延时没有做周期计时，500/3000 不能当作经仪器确认的毫秒数。

## 复现与经验

详见 `实验操作说明.md`。`flash_sd.py` 包含原读卡器序列号、型号与容量检查，应先核对实物并审阅代码；不要照抄历史 `/dev/sde`。仓库只归档脚本，不执行磁盘写入。裸机程序未实现串口打印，串口安静不能单独判为程序未启动。

原始参考仅收录 `官方裸机例程/1_leds` 与 `2_ledc`，来源为正点原子 `imx6ull-bareARM`，提交 `fc3499320e7456bebdc981501e22279f60c028ce`。`prepare_build.py` 用来重建四种工程。
