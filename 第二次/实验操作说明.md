# I.MX6ULL ALPHA 裸机 LED 实验

## 当前实测进度（2026-10-16）

- Windows 已识别 USB-SERIAL CH340 (COM3)，115200 波特率，串口返回 `root@ATK-IMX6U:~#`。
- WSL 发行版为 `sweet`，版本为 WSL 2。
- 已安装 ARM GCC 13.3.0、ARM binutils 和 usbipd-win 5.3.0。
- USB 读卡器 VID:PID 为 `067b:2731`，本次 BUSID 为 `2-14`。
- SD 卡容量 31,270,109,184 字节（标称约 32GB）；接入 WSL 后本次设备为 `/dev/sde`。
- 汇编常亮、汇编熄灭、C 延时 500、C 延时 3000 四个工程均已编译，并生成带官方 512MB DDR 初始化配置的启动镜像。
- 已将 `c_500` 烧录到 SD 卡，读回校验一致。用户按 SD 启动流程操作后现场反馈“闪烁”，确认默认延时版本的用户 LED 闪烁效果；未进行周期计时，也未收到现场视频。
- `c_3000` 已于北京时间 12:17:07 烧录并通过读回校验，用户现场确认亮和熄灭的时间明显变长，慢闪效果通过。
- 汇编常亮版本已于北京时间 12:24:09 烧录并通过读回校验，用户现场确认常亮符合预期。汇编熄灭版本已于北京时间 12:26:28 烧录并通过读回校验，用户现场确认电源灯亮、用户 LED 熄灭，符合预期。现场结果见 `实测记录/LED实验现象记录.md`。
- 四组实验均已完成板上效果确认；当前 SD 卡保留汇编熄灭版本。四组结果详见现场现象记录。

## 1. 检查环境

在 Windows PowerShell 中：

```powershell
wsl -l -v
```

在 WSL Ubuntu 中：

```bash
arm-linux-gnueabihf-gcc --version
make --version
```

本次工程明确增加 `-mcpu=cortex-a7 -marm -fno-pie -ffreestanding`，使当前 Ubuntu 编译器生成与裸机启动方式匹配的 ARM 指令。

## 2. 将 USB 读卡器交给 WSL

打开 WSL，插好读卡器和 SD 卡。在管理员 PowerShell 中首次共享：

```powershell
& 'C:\Program Files\usbipd-win\usbipd.exe' list
& 'C:\Program Files\usbipd-win\usbipd.exe' bind --busid 2-14
```

然后连接：

```powershell
& 'C:\Program Files\usbipd-win\usbipd.exe' attach --wsl --busid 2-14
```

本次 BUSID 是 `2-14`，换 USB 接口后必须重新查看，不要固定照抄。在 WSL 中确认：

```bash
lsusb
lsblk -b -o NAME,SIZE,MODEL,SERIAL,TRAN,TYPE,MOUNTPOINTS
```

必须同时看到 USB 读卡器和对应块设备。USB 枚举可能需要几秒。通过 Windows 盘符访问文件不能替代原始磁盘访问。

## 3. 编译程序

例如在 WSL 中编译 C 语言默认版本：

```bash
cd /mnt/d/Develop/Linux/嵌入式/裸机LED实验/工作工程/c_500
make clean
make
```

`start.S` 设置 SVC 模式和栈，跳转到 `main`。`main.c` 配置时钟和 GPIO，然后循环关灯、延时、开灯、延时。链接地址为 `0x87800000`。

## 4. 烧录并校验

每次烧录前重新核实卡的容量、型号、USB 总线和实际设备名，并确保分区未挂载。工程的 `flash_sd.py` 会检查本次读卡器身份，先备份原区域，再写入并校验。

本次实际使用的命令为：

```bash
sudo python3 /mnt/d/Develop/Linux/嵌入式/裸机LED实验/flash_sd.py c_500 /dev/sde --write
```

`/dev/sde` 只是本次的设备名，下次可能变化。脚本写入 `load.imx` 到整卡偏移 1024 字节处，保留前 1024 字节和写入范围外的数据，不格式化 SD 卡。

官方 `imxdownload` V1.1 的帮助文字与实际参数顺序不一致。本次已核对实际用法：

```bash
sudo ./imxdownload ledc.bin sd-image.img -512m
```

这里的目标是普通镜像文件，仅用于生成和核对镜像；物理 SD 卡写入由上述身份检查脚本执行。`load.imx` 含启动头和 DDR 初始化数据，不能把裸 `.bin` 简单复制到卡内代替烧录。

## 5. 开发板启动与观察

1. 烧录后完成同步，在 PowerShell 中释放读卡器：

   ```powershell
   & 'C:\Program Files\usbipd-win\usbipd.exe' detach --busid 2-14
   ```

2. 开发板断电，从读卡器取出卡，插入开发板 TF 卡槽。
3. 根据板上标注的 SD 启动配置设置 BOOT 拨码，不混用其他开发板的拨码定义。
4. 重新上电，观察用户 LED。裸机 LED 程序没有串口打印，串口安静不能单独判定为失败。
5. C_500 应反复亮灭；确认后再断电，取卡接回电脑，重新连接 WSL 并烧录 C_3000。
6. C_3000 应比 C_500 闪烁慢。教材的忙等待延时受主频和编译结果影响，应以实际观察为准。
7. 汇编版同样分别烧录 `asm_on` 和 `asm_off`，验证亮与灭。

如果仍出现 Linux 启动日志，应检查是否仍在从 eMMC 启动。如果没有闪烁，需要联合检查电源、卡槽、拨码、镜像和 GPIO 配置，不能仅凭串口无输出下结论。
