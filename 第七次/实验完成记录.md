# 实验七 Qt控制LED完成记录

实验日期：2026年10月16日。

## 完成结果

- 主机交叉编译成功：ARM 32位小端 EABI5 Linux ELF，动态链接。
- 板端运行成功：Qt 5.12.9，真实 Linux framebuffer，1024×600。
- 通过 Qt 按钮控制 /sys/class/leds/sys-led/brightness，依次读回 1、0、1，三次验证全部 PASS，failures=0。
- 用户现场确认：“实体LED能随按钮亮灭”。

## 硬件与运行环境

正点原子 I.MX6ULL ALPHA，Linux 4.1.15-g3dc0a4b，Qt 5.12.9，glibc 2.23，libstdc++.so.6.0.21。串口 COM3，115200，8N1；开发板 eth0 为192.168.1.4，电脑有线192.168.1.100。网线接ENET2。

LED节点：/sys/class/leds/sys-led。原触发模式为heartbeat。Qt程序启动时记录原模式并写none，点击按钮先读取真实brightness再写相反值，写后再次读取。正常退出恢复原触发模式。

屏幕：/dev/fb0，1024×600。Qt平台为linuxfb。触摸屏为goodix-ts，/dev/input/event1。使用板端现有字体SourceHanSansCN-Regular.otf。

## 实际编译方式

采用老师允许的命令行交叉编译方式。本地未找到正点原子Poky SDK，因此没有伪称已安装该SDK或配置Qt Creator。

实际建立了适用于本次Qt Widgets工程的交叉编译环境：

1. Linaro GCC 5.5-2017.10 ARM hard-float编译器。
2. Qt官方5.12.9源码，生成同版本qmake、公开头文件和模块配置。
3. 从此开发板复制既有Qt Core/Gui/Widgets及依赖库到主机sysroot，链接时使用板端库。

环境目录在WSL sweet：/home/little/lab7-sdk。源码位于qtbase-everywhere-src-5.12.9；配置位于configure-build；板端库副本位于board-sysroot。没有替换开发板系统Qt、libc或固件。

Qt 5.12主机工具在Ubuntu 24.04/GCC 13下缺少显式limits引用，已在主机源码副本中补充包含。板端GNU ld脚本中绝对路径仅在主机sysroot副本重定位。相关步骤保存于tools/prepare_sdk.sh、tools/build_arm.sh。

最终程序：bin/qt_led_arm。完整源码：qt_led/main.cpp、qt_led/qt_led.pro。编译日志：build/arm/build.log。符号需求：实测记录/ARM符号版本.txt。板端ldd全部依赖找到，最终链接日志无缺库警告。

## 板端文件和启动方式

独立工作目录为/home/root/lab7：qt_led_arm、run_on_board.sh、run2.log及evidence。

```sh
cd /home/root/lab7
sh ./run_on_board.sh
```

启动脚本暂时暂停原QDesktop进程以避免两个程序绘制同一屏幕，程序退出后恢复原桌面。没有删除或终止出厂桌面、修改开机配置。

复现实验自动验证：

```sh
cd /home/root/lab7
sh ./run_on_board.sh --verify
```

自动验证持续约8秒，期间忽略触摸输入，结束后恢复手动操作。程序先设灭，再经真实按钮槽执行亮、灭、亮并读取设备状态，截图保存在板端evidence目录。

同一时刻只运行一个实验程序。当前程序仍在运行，直接触摸按钮即可；需要退出时点击底部“退出并恢复原LED触发模式”，再重新运行以上命令。
